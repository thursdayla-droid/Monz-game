# カードパック＆カードバトル 設計案（2026-10-21・まだ実装しない）

企画者の指示書「MONZ 新機能仕様：カードパック＆カードバトル」への設計案。**企画者の承認後に、段階ごとに作る。**

## 確定（指示書より）
- ショップでカードパックを買う。1パック500コイン（【仮】ではなく指示書の値）。1パックでランダムに1枚
- 手に入れたカードは保存する。カード図鑑で見られる。開けるときに演出を入れる
- カードのランクは D・C・B・A・S の5段階（高いほどめずらしい）
- 能力は6つ（HP・攻撃・防御・魔法・素早さ・命中）。それぞれ D〜S の5段階。**カードのランクと能力のランクは別**（ランクBで攻撃Sもありえる）
- 新しいミニゲーム「MONZ CARD BATTLE（仮称）」。今の「MONZ CARD」（トランプ）とは別
- 持っているカードから3枚を選ぶ。1対1で、1体ずつ場に出して戦う
- 最初の先攻は、場に出ているMONZの素早さが高い方。そのあとは毎ターン攻撃と防御が必ず入れかわる
- 攻撃側のコマンド：こうげき・必殺・魔法・特殊（特殊は持っているMONZだけ）
- 防御側のコマンド：防御・カウンター・魔法防御・特殊（同上）
- 相性（決まっているもの）

| 攻撃 \ 防御 | 防御 | カウンター | 魔法防御 |
|---|---|---|---|
| こうげき | ダメージ軽減 | 成功・通常より大きいダメージ | **未確定** |
| 必殺 | 成功・大ダメージ | カウンター成功 | 成功・大ダメージ |
| 魔法 | 成功 | 成功 | ダメージ0 |

- カウンターが成功するのは「必殺」に対してだけ
- 特殊を持つカードは少しだけ。MONZごとにちがう。強すぎない
- ランクや能力だけで勝負が決まらない。相手の行動を読んだ人が勝てる。SはBに有利だが無敵ではない
- 既存のゲームのキャラ・画面・技名・演出はまねしない

## 未確定（勝手に決めない）
- カードの総数、どんなMONZのカードか、重なったとき（同じカードが2枚目）の扱い、出る確率、ランクの正式な名前
- 能力の中の数字・ダメージの計算・命中率
- こうげき×魔法防御、カウンターされた必殺のダメージ、魔法のダメージ
- 特殊の種類・効果・回数・条件
- 素早さが同じときの先攻
- MONZが倒れて交代したあとの攻守
- 勝ち方（相手の3体を全部倒したら勝ち、で確定してよいか）
- ミニゲームの報酬（ルールは画面に書かない方針）

## 設計案
### カードの一覧と持っているカード
- カードの一覧表（src/core/cards.ts）：番号・名前・MONZ・カードのランク・6能力のランク・特殊（あれば）・絵
- 持っているカードは保存データに「カードの番号ごとの枚数」で入れる。重なりの扱いが決まっていなくても、枚数を残しておけば後で決められる
- パックを開ける：ランクごとの確率で1枚えらぶ（確率は【未確定】。種から同じ結果を出せる乱数を使う）

### カード図鑑
- すべてのカードを番号順に並べる。持っていないカードは黒いシルエット（見せ方は確認したい）
- ランクでしぼりこみ。タップでくわしく（6能力のランク・特殊・持っている枚数）
- 「○/○枚 集めた」を出す

### バトルのしくみ
- 画面（Phaser）と、ルールの計算（src/core/、Phaserなし）を分ける。ルールの計算だけで何千回も対戦させて、強さの調整ができるようにする
- 1ターン：攻撃側と防御側が同時にコマンドを選ぶ → 相性の表で結果を決める → 命中の判定 → ダメージ → HPが0なら交代 → 攻守交代
- 相性は表1つにまとめる。決まっていないマスは「未確定」のまま残し、決まったら表に書き込むだけで変えられるようにする
- 能力のランク（D〜S）→ 数字への置きかえも表1つにする（数字は【未確定】。テストとシミュレーションで決める）

### CPUの読み合い
- CPUはプレイヤーが今選んだコマンドは見ない（ずるをしない）
- これまでのプレイヤーのくせ（例：必殺をよく使う）を覚えて、それに強いコマンドを選びやすくする
- ただし毎回いちばん良い手は選ばない（読まれにくくするため、少しばらつかせる）。ばらつきの大きさで強さを変えられる

### バランスの調整
- CPUどうしで何千回も対戦させる。S入りのデッキとB入りのデッキで勝率を見る
- 目標の勝率（例：B側が35〜45%くらい勝てる）は企画者と決める
